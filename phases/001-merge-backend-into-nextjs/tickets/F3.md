# F3 — Budgets

**Feature** `../tasks.md#feature-3-budgets` · **Design** `../tdd.md#api-contracts` · **Story** US3

## Goal

Port `dime-api`'s `budgets` module into `dime-web` as Next.js Route Handlers backed by a
framework-agnostic service layer, so `dime-web` serves `GET/POST /api/budgets`,
`PATCH/DELETE /api/budgets/:id`, and `GET /api/budgets/:id/progress` with contract parity to
`dime-api` — including the per-period spend computation (`budgets.period.ts`) and its batched,
type-grouped aggregation query. This is the third ported module, following F1/F2's established
route/service/test conventions.

## Decisions

| Question | Answer | Why |
|---|---|---|
| `tdd.md`'s API contracts table says `POST`/`PATCH` `/api/budgets*` return a bare `Budget` | Wrong — corrected to `{budget: Budget}` (wrapped) | `dime-api`'s actual source (`budgets.routes.ts:61` `reply.code(201).send({ budget })`, `:91` same for PATCH) wraps it, and `dime-web`'s own already-shipped frontend client (`lib/api/budgets.ts`, `createBudget`/`updateBudget` both typed `Promise<{ budget: Budget }>`) already depends on that shape in production code. Identical class of correction to F1's categories fix and F2's transactions fix. |
| `tdd.md`'s API contracts table says `GET /api/budgets/:id/progress` returns a bare `BudgetProgress` | Wrong — corrected to `{budget: Budget, spent, remaining, percent, daysRemaining, periodStart, periodEnd}` (the `budget` object merged in alongside the progress fields, not a separate wrapper key) | `dime-api`'s source (`budgets.service.ts:132`: `return { budget, ...buildProgress(...) }`, sent as-is by `budgets.routes.ts:41`) returns this exact shape, and `dime-web`'s `lib/api/budgets.ts` already types `getBudgetProgress` as `Promise<BudgetProgress>` where `BudgetProgress` includes a nested `budget: Budget` field. |
| `dime-api`'s schema uses `z.string().cuid(...)` (deprecated in the installed Zod v4) for `categoryId` and the `:id` param | Use top-level `z.cuid(...)` | Matches the non-deprecated precedent already established in `categories.schema.ts` (F1) and carried forward in `transactions.schema.ts` (F2); avoids the deprecated form `tdd.md`'s own Architecture row flags. |
| `listBudgets` batches spend aggregation with one grouped `transaction.groupBy` per distinct budget `type` (at most 4 queries total), rather than one aggregate query per budget | Preserve exactly as written, no simplification | This is a deliberate perf choice in the source (see its own doc comment), not incidental complexity — collapsing it to a per-budget loop would be an unrequested behavior change on a port ticket, and would turn an O(types) query count into O(budgets). |

## Not verified

- `checkRateLimit`'s Postgres upsert concurrency is asserted by a mocked-Prisma unit/contract test, not
  a real concurrent-request test against Postgres — matches every other service-layer test in this port
  (F0/F1/F2 included).
- Zod v4's *default* (non-custom) validation message wording differs from the v3-era source; status
  codes, envelopes, and every custom message are unaffected — a library-version difference, not a port
  regression, per the same note recorded in F1.md/F2.md.
- `e2e/budgets.spec.ts` already exists but its direct API calls (e.g. `foodCategoryId`'s
  `api.get('/api/categories')`) still resolve against `dime-api` (`e2e/helpers/api.ts`'s hardcoded
  `API_URL = 'http://localhost:4000'`), not `dime-web`'s new routes. Retargeting it is `T027`'s job,
  after auth is ported in Feature 7.
- The batched groupBy query's performance characteristic (at most 4 queries regardless of budget count)
  is confirmed by call-count assertions against a mock, not a load test.

## Out of scope

- Any change to `dime-api` itself.
- `/api/analytics/budget-vs-actual` — Feature 5. It reuses `listBudgets` per `tdd.md`, but wiring that
  endpoint up is not this ticket's job.
- The frontend cutover (`lib/api.ts`'s same-origin base URL) — Feature 9. `lib/api/budgets.ts`,
  `hooks/useBudgets.ts`, `components/budgets/*`, and `app/(app)/budgets` already exist and already
  expect this ticket's exact (corrected) contract, but won't actually reach `dime-web`'s routes until
  Feature 9 repoints the base URL.
- `Budget.amount`'s `Float` storage precision risk — carried over as-is per `LEARNINGS.md`, not fixed
  in this phase.
- Auth routes — Feature 7.
