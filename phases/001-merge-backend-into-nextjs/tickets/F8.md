# F8 — CSV import/export

**Feature** `../tasks.md#feature-8-csv-importexport` · **Design** `../tdd.md#api-contracts` · **Story** US8

## Goal

Port `dime-api`'s `csv` module into `dime-web` as Next.js Route Handlers backed by a framework-agnostic
service layer, so `dime-web` serves `GET /api/csv/export`, `POST /api/csv/import/preview`, and
`POST /api/csv/import/commit` with contract parity to `dime-api` — preserving the export's exact bytes
(UTF-8 BOM, headers, `Content-Disposition`), the two-step signed-token import flow, and the
all-or-nothing chunked commit. Last of the eight ported modules, per the TDD's own sequencing (most
Fastify-specific plumbing — multipart, streaming — so it benefits most from every other module's route
pattern already being proven).

**Running fully autonomously, per explicit operator override.** This session has no interactive human
available: step 3 ("Ask") is replaced by deciding each open question myself, from the TDD / the live
`dime-api` source / existing `dime-web` convention, and recording it below marked **"decided
autonomously — no human available this session"**; step 5's mandatory pause is skipped and I proceed
straight to code once the spec is committed, per explicit operator instruction.

**Step 5 check (stop-list), done for the record rather than silently skipped:** this feature touches
none of the four items — no authentication/authorization *decision* logic (routes reuse the existing
`authenticate`/`checkRateLimit` helpers unchanged, same as every prior module), no money movement (CSV
rows create `Transaction` records the same way `POST /api/transactions` already does — not itself flagged
for F2 either), no migration or destructive operation (no schema change; import only ever creates rows,
never updates/deletes), and no new concurrency primitive (the commit's `$transaction` is a plain
all-or-nothing bulk insert, not a lock/isolation-level/counter/idempotency-key — the TDD explicitly
reserves that "concurrency primitive" label for ledger's `settleAll` optimistic-concurrency check, F6).
**No stop-list item fired.** Proceeding straight to code per the operator's explicit override of step 5
regardless.

There is no `rows` field. **Decided autonomously — no human available this session.** | The TDD's own project-structure list marks `csv.service.ts` "copied verbatim" — the actual `dime-api` source (`csv.service.ts:185-227`) is the contract, not the contracts table's loose one-line gloss. Identical class of "TDD documented an imprecise/wrong shape" correction F1 through F5 each made once for their own module (`LEARNINGS.md` names this as a pattern worth re-checking on every remaining row). |
| `tdd.md`'s contracts table says commit's success status is `200` and folds "token invalid/expired, or file hash doesn't match" into a single `400` row | Wrong on both counts — commit succeeds with **`201`** (`csv.routes.ts`: `reply.code(201).send(result)`, confirmed by `csv.test.ts`'s own `expect(res.statusCode).toBe(201)`), and a file-hash mismatch is **`409`**, not `400` (`csv.service.ts`'s `commitImport` explicitly `throw httpError(409, ...)` for that case, confirmed by `csv.test.ts`'s `expect(res.statusCode).toBe(409)`); only a malformed/expired/wrong-user token is `400`. **Decided autonomously — no human available this session.** | Same class of correction as the row above — the live `dime-api` source and its own test suite are the authoritative contract, not the contracts table's compressed prose. `409` also matches `lib/server/errorResponse.ts`'s existing `CONFLICT` code, which every other module already uses for an app-level conflict (e.g. categories' duplicate-name 409). |
| No env var name exists anywhere for the CSV-export rate-limit override (`tdd.md` only says "10/min CSV-export override" in prose; the route-group key `"csv-export"` itself is already fixed by `rateLimit.test.ts`'s existing test and the TDD's Data model example row, so that part isn't a new decision) | `RATE_LIMIT_CSV_EXPORT_MAX`, default `10`, reusing the existing `RATE_LIMIT_WINDOW_SECONDS` for the window (dime-api's own override only changes `max`, not the window, from its plugin-wide default). **Decided autonomously — no human available this session.** | Follows the exact naming shape `docs/operations.md` already documents for `RATE_LIMIT_MAX`/`RATE_LIMIT_WINDOW_SECONDS` — same prefix, same optional/default pattern, discoverable next to the variable it overrides rather than inventing an unrelated name. |
| How to structure per-route file-upload validation (file present, `.csv` extension, `File.size` ≤ 2MB) shared by `import/preview` and `import/commit` | Duplicate the small validation block in each route file rather than factor out a shared helper module | Matches this codebase's own already-established convention: `envNumber`/`checkGlobalRateLimit` are duplicated verbatim in every existing route file (`transactions/route.ts`, `budgets/[id]/progress/route.ts`, etc.) rather than imported from one shared module. Consistency with that precedent outweighs the small amount of duplication, per the `ticket` skill's step 2 ("the codebase's conventions beat any convention you would pick, including a better one"). |
| Are `import/preview`/`import/commit` subject to the global rate limit, or exempt like `/api/health`? | Subject to the global limit (`checkGlobalRateLimit`, same as every other mutating route) | Not itself ambiguous: `dime-api`'s `csv.routes.ts` registers no per-route `config.rateLimit` on either route, so both inherit the plugin-wide default (`@fastify/rate-limit`'s global registration) — only `export` overrides it down to 10/min. `dime-web`'s equivalent is applying `checkGlobalRateLimit` to preview/commit and a distinct `checkExportRateLimit` only to export. |

before `file.arrayBuffer()` in both import routes, per the TDD's Architecture table; the mid-transaction
failure test (`csv.service.test.ts`, "a failure partway through the chunk loop propagates rather than
completing a partial import") confirms a chunk-loop rejection isn't swallowed into a false success — actual
atomic rollback is Postgres's own `$transaction` guarantee, unchanged from `dime-api`, not something a
mocked Prisma client can itself exercise; no stray `console.log`/debug output in any new file; `git status`
after the full evidence-gathering pass shows no untracked files (all curl artifacts went to `/tmp`, not the
repo). Nothing required a code change.

One real, non-obvious finding surfaced while writing the route-level BOM assertion (not a defect in the
shipped code, since the actual route never calls `.text()` on its own output) — `Response.text()`'s
`TextDecoder` strips a leading UTF-8 BOM by default, so an initial test written against
`(await response.text()).charCodeAt(0)` failed even though the live curl evidence below shows the real wire
bytes are correct. Fixed by reading `response.arrayBuffer()` instead and asserting the raw `0xef 0xbb 0xbf`
prefix; recorded in `LEARNINGS.md` since the same trap would silently hide a real BOM regression in any
future route that emits one.
