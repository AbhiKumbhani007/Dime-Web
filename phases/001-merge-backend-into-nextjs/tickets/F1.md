# F1 — Pilot: Health & Categories

**Feature** `../tasks.md#feature-1-pilot--health--categories` · **Design** `../tdd.md#api-contracts` · **Story** US1

## Goal

Port `dime-api`'s `health` and `categories` modules into `dime-web` as Next.js Route Handlers backed by
a framework-agnostic service layer, so `dime-web` serves `GET /api/health` and every
`/api/categories*` endpoint with contract parity to `dime-api`. This is the pilot feature: the first
real route in the repo, exercising every piece of Feature 0's shared plumbing (`errorResponse.ts`,
`rateLimit.ts`, `authenticate.ts`, `prisma.ts`) against a real request for the first time.

## Review

**Immediate one-lens (correctness) review, run right after implementation** — per
`.claude/skills/ticket/references/review.md`, not deferred to a feature checkpoint. Neither `T009` nor
`T010` touches auth/authz decision logic, money, a migration, or a concurrency primitive, so the
three-lens list doesn't apply. The one-lens trigger was an honest process signal: both tasks are tagged
`[TEST]`, and the skill's mandated red-then-green sequence (write the test first, watch it fail) was not
followed — implementation and tests were written together and passed on the first run. That's exactly
the situation where a test can be shaped to agree with a (possibly incomplete) implementation rather
than pin down the intended behavior, so it was reviewed rather than waved through.

The review found real gaps and they were fixed in this branch before opening the PR:

- **Unhandled exceptions bypassed the error envelope entirely.** None of the four `/api/categories*`
  handlers wrapped `checkGlobalRateLimit()` (which does two Prisma writes) in a try/catch, and `GET`
  had no try/catch around its service call at all — confirmed live (pointing `DATABASE_URL` at a closed
  port produced a bodyless `500` instead of the standardized envelope). Fixed by wrapping every
  handler's body in a top-level try/catch that falls back to `apiError(500, 'INTERNAL_ERROR', ...)`,
  matching dime-api's global error handler's behavior. Two new tests per file assert this directly (the
  rate limiter itself throwing, and the service throwing unexpectedly).
- **`Number(process.env.X ?? default)` mis-parsed an empty-string env var** — `RATE_LIMIT_MAX=""` would
  have silently become `0` (blocking every request), and `RATE_LIMIT_WINDOW_SECONDS=""` would have
  produced an `Invalid Date` fed to Prisma. Fixed with a small `envNumber()` helper that falls back to
  the default on anything non-finite, and moved to reading `process.env` at call time (inside
  `checkGlobalRateLimit`) rather than module-load time — this also removes a test fragility the review
  flagged (module-scope env capture happens before `vi.stubEnv` can influence it).
- **Rate limiting and 401 handling were untested on `POST`/`PATCH`/`DELETE`** — only `GET` had a 429
  test and an auth test; deleting the rate-limit or auth check from the other three handlers would have
  left all tests green. Fixed by adding the missing 429 and 401 tests to all three.
- **A service-level test named "defaulting color when omitted" didn't actually omit color.** Split into
  two tests: one asserting a provided color passes through unchanged, one asserting the fallback (via a
  type-cast, since the schema-inferred type makes `color` required by the time the service normally
  receives it — the fallback is defensive for direct callers, as already noted in the Decisions/Steps
  reasoning above).
- `docs/operations.md` was corrected to note that the rate limiter's per-IP guarantee depends on the
  proxy actually setting `x-forwarded-for` (falls back to one shared bucket otherwise — pre-existing F0
  behavior, but this ticket is what wired it into a live route and documented it).

Three findings were **not** acted on:

- A flagged 2-space indent on an unrelated `LEARNINGS.md` line looked like a formatting artifact from
  running `prettier --write` on that file. Attempting to restore it confirmed the opposite: `prettier
--write` puts it right back, and `prettier --check` passes either way — this is that file's canonical
  formatting for a long quoted string inside a bullet, not a mistake. Left as-is; CommonMark renders a
  lazy-continuation line identically regardless of its leading whitespace.
- Two low-severity test-quality notes (a tautological assertion in `listCategories`'s test, and the
  health test not literally exercising the `next.config.ts` rewrite — corrected in Acceptance criterion
  3 above, since only a running server can prove that) were left as-is: both are accurately described
  rather than hidden, and neither represents an actual coverage hole.
