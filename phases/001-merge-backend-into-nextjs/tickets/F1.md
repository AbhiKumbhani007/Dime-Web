# F1 — Pilot: Health & Categories

**Feature** `../tasks.md#feature-1-pilot--health--categories` · **Design** `../tdd.md#api-contracts` · **Story** US1

## Goal

Port `dime-api`'s `health` and `categories` modules into `dime-web` as Next.js Route Handlers backed by
a framework-agnostic service layer, so `dime-web` serves `GET /api/health` and every
`/api/categories*` endpoint with contract parity to `dime-api`. This is the pilot feature: the first
real route in the repo, exercising every piece of Feature 0's shared plumbing (`errorResponse.ts`,
`rateLimit.ts`, `authenticate.ts`, `prisma.ts`) against a real request for the first time.

## Decisions

| Question | Answer | Why |
|---|---|---|
| Wire the rate limiter into F1's routes, even though T009/T010's task text never mentions it? | Yes — wire `checkRateLimit`/`rateLimitKey` into all 4 `/api/categories*` handlers; exempt `/api/health` | TDD's Architecture row commits to a uniform 100/min default and F0 explicitly deferred wiring to "Feature 1+"; F1 is the first route to exist, so it's the natural place to close that gap. `/api/health` is exempted deliberately — a deviation from dime-api's literal current behavior (which does rate-limit `/health` per `fixtures/README.md`) — justified by Kuberns' platform health probes hitting it on a fixed interval; dime-web's limiter costs a Postgres write per check where dime-api's in-memory one was free, and a probe tripping 429 risks a false-unhealthy signal. |
| `checkRateLimit(key, limit, windowSeconds)` takes a numeric window, but dime-api's `RATE_LIMIT_WINDOW` env var is a Fastify duration string (`'1 minute'`) | Reuse `RATE_LIMIT_MAX` (same name/meaning, integer, default `100`); introduce a new var `RATE_LIMIT_WINDOW_SECONDS` (numeric seconds, default `60`) instead of reusing `RATE_LIMIT_WINDOW` | The two vars mean different things by type; reusing a name across a string-duration and numeric-seconds config is a silent footgun for whoever sets Kuberns' env config later. |
| tdd.md's contracts table says F1's checkpoint is verified by `e2e/categories.spec.ts` pointed at dime-web | Reworded — verified by `categories.routes.test.ts` + `health/route.test.ts` (contract level) plus one manual curl session against a running dime-web dev server, pasted into the PR | Not achievable as written: `e2e/helpers/api.ts`'s `registerTestUser`/`authedContext` both hit a single hardcoded `API_URL` (dime-api, `:4000`) for both auth and categories, and auth itself isn't ported until Feature 7 (`T021`/`T022`). Splitting register (dime-api) from category calls (dime-web) needs new test infra that belongs to `T027`. |
| tdd.md's API contracts table says categories POST/PATCH return bare `201 Category`/`200 Category` | Wrong — corrected to `201 {category}` / `200 {category}` (wrapped) | Matches both the source (`dime-api/.../categories.routes.ts`: `reply.code(201).send({ category })`) and dime-web's own already-shipped frontend client (`lib/api/categories.ts`, typed `Promise<{ category: Category }>`). Only the GET list envelope was previously live-verified; POST/PATCH's row was simply wrong. |
| `updateCategory`/`deleteCategory`'s two inline 404 constructions vs. the `httpError()` helper T007 already ships | Use `httpError(404, 'Category not found')` | Byte-identical resulting error object; the helper every other dime-api service (`ledger`, `csv`, `templates`, `budgets`) already uses for this — categories simply inlined it in the source. A one-line, worth-recording deviation from "verbatim," not a design change. |

## Not verified

- `e2e/categories.spec.ts` is not pointed at dime-web (Decision #3) — it still runs entirely against
  dime-api. Retargeting it is `T027`'s job, after auth is ported in Feature 7.
- `checkRateLimit`'s Postgres upsert concurrency is asserted by a mocked-Prisma unit/contract test, not
  a real concurrent-request test against Postgres — matches every other service-layer test in this
  port.
- Zod v4's *default* validation message for a missing required field differs from the live-captured v3
  fixture (`"Required"` → v4's longer default text). Status, envelope, and every custom message are
  unchanged — this is a library-version difference, not a port regression.

## Out of scope

- Any change to `dime-api` itself.
- `e2e/categories.spec.ts` / `e2e/helpers/api.ts` — untouched per Decision #3; owned by `T027`.
- The frontend cutover (`lib/api.ts`, `SessionProvider.tsx`) — Feature 9.
- Auth routes — Feature 7; F1 only consumes the existing `authenticate()` helper.
