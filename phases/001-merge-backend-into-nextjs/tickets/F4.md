# F4 — Templates

**Feature** `../tasks.md#feature-4-templates` · **Design** `../tdd.md#api-contracts` · **Story** US4

## Goal

Port `dime-api`'s `templates` module into `dime-web` as Next.js Route Handlers backed by a
framework-agnostic service layer, so `dime-web` serves `GET/POST /api/templates` and
`PATCH/DELETE /api/templates/:id` with contract parity to `dime-api` — including the three-way `sort`
query param and category-ownership checks on create/update. Fourth ported module, following
F1/F2's route/service/test conventions.

## Review

**Checkpoint review, run after T016** — per `.claude/skills/ticket/references/review.md`. F4 doesn't hit
the three-lens-immediately list (no auth/authz decision logic, money, a migration, or a concurrency
primitive — it's CRUD on a preset-chip model with an existing-user-owned FK check) and no honest-signal
override fired (both `[TEST]` tasks followed the mandated red-then-green sequence, no approach change,
no scope surprise). Since F4 is a single-ticket feature, its checkpoint is this review, run against the
full `main...F4-templates-port` diff (8 finder angles, 1-vote verify on each surviving candidate).

One real gap was found and fixed in this branch before opening the PR:

- **`createTemplate`/`updateTemplate`'s `categoryId` ownership check isn't atomic with the write.** A
  category deleted between the `findFirst` ownership check and the `create`/`update` call surfaced as a
  raw Prisma `P2003` foreign-key violation, which neither function's catch block matched — the client got
  a generic `500 INTERNAL_ERROR` instead of the documented `404 NOT_FOUND`. Fixed by catching `P2003` in
  both functions and mapping it to `httpError(404, 'Category not found')`, with a dedicated test per
  function asserting the 404 (not a raw rejection) when the write itself fails with `P2003`.

Two cleanup findings were reported but not acted on in this ticket:

- **`envNumber`/`checkGlobalRateLimit` and the per-handler auth `try/catch` are now duplicated across 4
  route files** (categories' 2, templates' 2) with no shared helper — the same boilerplate that needed a
  hand-patched fix once already (`bb95205`, categories-only). Real and worth fixing, but the fix means
  extracting shared helpers into `lib/server/rateLimit.ts`/`lib/server/auth/` **and** updating the
  already-merged categories route files — a cross-cutting refactor beyond porting templates, and the kind
  of change that should be its own ticket, not smuggled into a feature port's diff.
- **`TemplateParamsSchema` hand-writes the cuid-param shape instead of using the existing `cuidParam()`
  helper.** Not acted on: `categories.schema.ts` (already merged) made the identical choice, so this
  matches established repo convention rather than introducing a new inconsistency — fixing it here alone
  would make templates diverge from categories, not converge.

Two things two independent finder angles suggested but that the verify pass refuted or ruled out of
scope:

- A parallel finding — the same TOCTOU shape on `updateTemplate`/`deleteTemplate`'s own-row
  existence-check-then-mutate (a concurrent double-request could hit Prisma's `P2025` instead of the
  intended 404) — was refuted as an F4-specific finding: `categories.service.ts`'s `updateCategory`/
  `deleteCategory` (already merged, shipped in F1) have the byte-for-byte identical structure. This
  ticket's code simply follows an already-accepted codebase convention rather than introducing a new gap.
- A frontend bug (`components/templates/TemplateForm.tsx` sends `note: undefined` instead of `note: null`
  when a user clears a note, so `PATCH` treats it as "unchanged" rather than clearing it) was surfaced by
  the cross-file tracer angle but is out of scope: `TemplateForm.tsx` isn't touched by this diff, and the
  same bug already exists against dime-api's live backend today (dime-web's frontend isn't cut over to its
  own routes until Feature 9) — it predates and is independent of this port.
