# F2 — Transactions

**Feature** `../tasks.md#feature-2-transactions` · **Design** `../tdd.md#api-contracts` · **Story** US2

## Goal

Port `dime-api`'s `transactions` module into `dime-web` as Next.js Route Handlers backed by a
framework-agnostic service layer, so `dime-web` serves `GET/POST /api/transactions` and
`GET/PATCH/DELETE /api/transactions/:id` with contract parity to `dime-api` — including cursor
pagination, category-ownership validation, and the optional `templateId` usage-bump side effect. This is
the second ported module, following Feature 1's now-established route/service/test conventions.

## Decisions

| Question                                                                                                                                                                     | Answer                                                                                                                                                         | Why                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

## Not verified

- `checkRateLimit`'s Postgres upsert concurrency is asserted by a mocked-Prisma unit/contract test, not a
  real concurrent-request test against Postgres — matches every other service-layer test in this port
  (F0's and F1's tests included).
- Zod v4's _default_ (non-custom) validation message wording differs from the v3-era source; status
  codes, envelopes, and every custom message are unaffected — a library-version difference, not a port
  regression, per the same note recorded in F1.md.
- `e2e/*.spec.ts` is not retargeted at `dime-web` — still `T027`'s job, after auth is ported in Feature 7.

## Out of scope

- Any change to `dime-api` itself.
- The frontend cutover (`lib/api.ts`'s same-origin base URL) — Feature 9. `lib/api/transactions.ts` and
  its consumers (`hooks/useTransactions.ts`, `components/transactions/*`, `app/(app)/log/page.tsx`)
  already exist and already expect this ticket's exact contract, but won't actually reach `dime-web`'s
  routes until Feature 9 repoints the base URL.
- Fixing the `PATCH {note: null}` gap — preserved exactly as documented in Decisions above.
- Auth routes — Feature 7.
